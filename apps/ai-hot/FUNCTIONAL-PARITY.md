## 验收边界

“功能相同”以公开提交的代码和行为为准。原站未公开的信源名单、数据库内容、管理员配置、外部服务密钥，以及后续未同步的线上改动，无法从仓库还原。独立安装有自己的数据，榜单缺少付费来源 key 时其结果也可能不同；这些属于运行配置，不应通过删代码或隐藏入口处理。

当前线上 `/tools/ai-hot/` 仍是旧 Worker 适配版。完整版本在完成真实部署、数据库验证、管理登录、外部服务配置与站内入口切换前，不能标为“100% 上线完成”。D1 的现有收录与反馈应先导出并迁移、核对，再切换；不直接删除旧数据。

完整原版直接从站点根路径运行。挂载到现有官网子路径需要验证路由、资源、登录回跳、RSS/API、MCP 和 SSR；不能仅使用路径重定向宣称已完整集成。

## 构建和部署

在 `fullstack/` 执行：

```sh
npm ci
node scripts/verify-upstream.mjs
npm run typecheck
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts
```

生产运行使用原版 `Dockerfile`、`docker-compose.yml` 和 `docs/deploy.md`。配置 `.env` 后，执行 `docker compose up -d --build`；setup 自动迁移和导入种子数据。不要将 `.env`、密钥、数据卷提交到仓库。

数据库测试必须使用专用、已迁移的 `*_test` / `*_ci` PostgreSQL 库，并关闭模型、采集及付费服务安全阀。上游测试套件随完整版本保留，不以旧适配版的测试数代替。
